Performance Wins

The Wrongful Infraction

A subdivision-mirror bug was quietly writing duplicate shifts onto officers' records. It wasn't just a data-quality issue — it was the actual root cause of a wrongful infraction someone received. Found, fixed, and the mirror logic now dedupes properly.

Shifts Were Being Written to the Wrong Guild

A stale environment-variable override, left over on the VPS from a previous debugging session, was silently pointing every dashboard-created shift at the wrong guild entirely — overriding the real CHP guild ID fallback with no warning anywhere. Removed.

The Roster That Only Showed 2 People

The Officers Roster was reading from an incomplete settings field and only ever showed two members, no matter how many officers actually existed. Switched to the guaranteed-complete rank-role list — the roster now shows everyone.

The One-Character Bug That Kept Crashing the Bot

A slash command's description string was exactly one character over Discord's 100-character limit. That alone was enough to crash-loop the entire bot on startup, repeatedly, until it was tracked down to that single field.

Bug Fixes

17 items
  • The pinned live leaderboard was reposting itself and losing its pin every hour — fixed twice, the second pass finally found the real root cause instead of another symptom.
  • The live leaderboard could crash outright when an update pushed a message past Discord's edit-size cap.
  • /ask's DM-redirect logic was over-triggering, and its confidentiality gate was refusing to answer things it should have answered.
  • A full stability pass on the Sergeant Exam: the View Answers screen hitting an invalid-form error, the Redo Question dropdown crashing on every use, the queue silently stalling when a release message failed to send, and its buttons breaking entirely after a bot restart.
  • The HR promotion review digest was pinging management every 12 hours instead of the intended once a month.
  • Every dashboard/bot endpoint threw a guild-unavailable error for a moment right after every bot restart.
  • This very changelog page: it defaulted to a nearly-blank first screen, had a white haze wash across most of the page, had a specular highlight that visibly chased your cursor around the screen, and had a stray character typo'd into the AI card's body text.
  • RA (Ride-Along) results could get double-recorded from a race condition — plus a new /ra void command to clean up any duplicates it already caused.
  • The HR oversight panel queried each officer's data one at a time and took roughly 10 seconds to load — now runs in parallel.
  • The Recognized Officers page took 60+ seconds to load because it fetched each avatar serially — now batched.
  • >duty active crashed on an unrecognized shift-type emoji, and >duty ping had a Components V2 content conflict.
  • HICOM Inactivity Review was silently producing zero output on startup — the actual cause was a before_loop hook, not the race condition everyone initially suspected.
  • The AI chat's streaming responses had a bug causing duplicate "done" events, plus no retry when Bedrock throttled a request.
  • Quota checks were comparing everyone against a hardcoded ~1-hour threshold instead of each member's real configured quota.
  • Leaderboard exports were hitting Discord's rate limit because they fetched live member data instead of using the cache.
  • Presence detection identified staff by parsing "HP-" out of their nickname instead of checking real role membership — quietly missed anyone who'd renamed.
  • AI vision (screenshot analysis) was timing out before it could actually finish processing an image — the timeout was raised so it reliably works now.

Quality of Life

12 items
  • Every plain Unicode emoji across the entire bot was replaced with the server's own custom branded emojis.
  • >agentchannel — the same AI tool-calling the dashboard uses, now available directly in a Discord channel.
  • A new public, officer-visible bot-logs channel mirrors non-confidential activity separately from the private staff-only audit log.
  • >devtest now auto-discovers newly tagged commands instead of needing a manual registry update.
  • !demote now takes an explicit target rank instead of guessing, and demotion appeals can actually be reversed.

  • Transfers were redesigned end-to-end: one single pinned status card with a visual step-tracker, replacing a scattered multi-message channel.
  • The leaderboard now pins your own position above the full list, and got a real period picker (week / month / year / custom range) with exports.
  • Historical channel scanning is now fully automated and self-heals daily — no more manual >chpscan required.
  • A weekly transfer-throughput digest now goes out to Command automatically.
  • /duty was trimmed from 18 subcommands down to 13 — several that genuinely overlapped were merged.
  • >help <command> now gives focused help for one command instead of dumping the entire category list.

Performance

6 items
  • The Officers Roster had a classic N+1 query problem — fixed by batching on-duty/watch lookups with a single $in query instead of two serial Mongo calls per officer.
  • Guild members are now pre-chunked at bot startup instead of being fetched lazily, speeding up officer/member lookups across the board.
  • The leaderboard card is now capped sensibly to stay under Discord's component character limits without silently truncating data.
  • Several missing or broken database indexes were added or fixed, covering LOA lookups, rank-change history, and whitelabel config caching.
  • Noisy CPU/memory/latency performance-alert DMs were quieted down to cut real alert fatigue.
  • This changelog page had roughly 20 simultaneous blur layers stripped out of its cards for a real, measurable memory reduction.

Security

3 items
  • Per-user rate limiting was added to the dashboard's AI chat, matching every other AI surface that already had it.
  • A denylist now guarantees no developer diagnostic tool can ever touch secrets or credentials, no matter what's asked of it.
  • Secret handling was hardened across both bridge authentication paths with timing-safe comparisons.
